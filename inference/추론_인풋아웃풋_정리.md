# 지하철 승하차 수요예측 — 추론 인풋/아웃풋 정리

> 역 1104 · 모델 v3 (`models/models_v3.pkl`) · 서빙: `inference/app.py` (Flask)
> 작성: 2026-07-20 · 예시 수치는 전부 실제 모델 실행 결과

---

## 1. 전체 흐름

```
[사용자 입력]  일시 하나 (예: 2026-07-21 08:30)
      ↓
[검증]  운행창(05:00 ~ 익일 00:10) 확인 — 밖이면 거부
      ↓
[피처 계산]  일시 → 달력 파생 피처 12개 자동 계산 (외부 데이터 불필요)
      ↓
[모델 추론]  LightGBM 8개 (타깃별 독립 모델, 동일 입력 공유)
      ↓
[후처리]  단조성 보정 (5≤15≤30≤60 강제, 음수는 0으로 클리핑)
      ↓
[아웃풋]  승차 4개 + 하차 4개 = 8개 예측값
```

핵심 특징: **입력은 일시 하나뿐.** 과거 실적(lag)이나 외부 API(날씨 등)가 전혀 필요 없어
과거·미래 아무 시점이나 예측 가능하다. (v1의 lag 26피처 구조를 v3에서 달력 피처만으로 재설계)

## 2. 인풋 — 일시 하나에서 피처 12개가 계산되는 규칙

입력 예시: **`2026-07-21 08:30`** (화요일)

| # | 피처 | 계산 규칙 | 예시값 |
|---|---|---|---|
| 1 | `hour` | 시각 (0~23) | 8 |
| 2 | `slot` | 하루 내 5분 칸 번호 = hour×12 + 분÷5 (0~287) | 102 |
| 3 | `dow` | 요일 (0=월 ~ 6=일) ※범주형 | 1 (화) |
| 4 | `month` | 월 (1~12) ※범주형 | 7 |
| 5 | `is_weekend` | 토·일이면 1 | 0 |
| 6 | `is_holiday` | 법정공휴일이면 1 (`holidays` 패키지 KR) | 0 |
| 7 | `is_major_holiday` | 설날·추석 연휴면 1 | 0 |
| 8 | `is_minor_holiday` | 명절 제외 일반 공휴일이면 1 | 0 |
| 9 | `holiday_prev` | 전날이 공휴일이면 1 (연휴 전후 효과) | 0 |
| 10 | `holiday_next` | 다음날이 공휴일이면 1 | 0 |
| 11 | `is_sandwich` | 평일인데 앞뒤가 모두 쉬는 날이면 1 | 0 |
| 12 | `is_yearend` | 12/24~31이면 1 (연말 특수) | 0 |

- `slot`이 피처 중요도 1위 — 하루 안에서의 위치(출근/점심/퇴근/심야)를 가장 정밀하게 표현
- 휴일 관련이 12개 중 7개 — 수요 패턴이 "평일/주말/명절/연휴전후"로 완전히 갈리기 때문

## 3. 아웃풋 — 8개 예측값

기준 시점 t 이후 **5 / 15 / 30 / 60분 창** 각각의 승차·하차 인원.

입력 `2026-07-21 08:30` 의 실제 추론 결과:

| | +5분 (~08:35) | +15분 (~08:45) | +30분 (~09:00) | +60분 (~09:30) |
|---|---|---|---|---|
| **승차** | 47명 | 138명 | 305명 | 640명 |
| **하차** | 47명 | 273명 | 522명 | 847명 |

- 출근 피크의 도심역 특성이 그대로 반영: 하차(847) > 승차(640)
- 모델 구조: 타깃 1개당 LightGBM 1개, 총 8개 (`y_board_5/15/30/60`, `y_alight_5/15/30/60`)
- 후처리: 창이 넓을수록 값이 크도록 누적 max 보정 (5≤15≤30≤60), 시작값 0이라 음수도 자동 제거

## 4. 예측 정확도 참고 (test: 처음 보는 미래 3개월)

| 창 | 승차 상대오차 | 하차 상대오차 |
|---|---|---|
| +60분 | 7.4% | 6.7% |
| +30분 | 9.4% | 7.8% |
| +15분 | 12.8% | 9.8% |
| +5분 | 20.2% | 15.1% |

창이 짧을수록 우연 변동 비중이 커져 어려움 — 이 트레이드오프 곡선 자체가 연구 결과.

## 5. 알아두면 좋은 현상 — 하차의 "열차 리듬"

13:40을 넣으면 하차 +5분이 2명으로 나오는데, 이는 오류가 아니라 실제 패턴이다.

평일 13시대 실측 평균 (train 18개월):

| 시각 | 승차 | 하차 |
|---|---|---|
| 13:35 | 66명 | **113명** |
| 13:40 | 69명 | **3.6명** |
| 13:45 | 55명 | **112명** |

- **승차** = 승객이 개찰구로 꾸준히 진입 → 5분마다 고르게 분포
- **하차** = 열차 도착 순간 한꺼번에 태그 → 배차 간격(낮 10분)에 맞춰 특정 5분 칸에 집중
- 모델이 이 배차 리듬까지 학습했다는 증거이며, +15분 이상 창에서는 열차 도착이 포함되며 값이 평활화됨

## 6. 서빙 스펙 (`app.py`)

| 항목 | 내용 |
|---|---|
| 실행 | `python app.py` → http://localhost:5000 |
| 입력 범위 | 오늘 ~ 3년 뒤 (달력 피처라 사실상 제한 없음, UI 편의상 제한) |

| 의존성 | flask, pandas, lightgbm, joblib, holidays (외부 API 없음) |
